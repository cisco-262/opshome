凭据保护

敏感凭据与普通监控数据分开处理

服务端敏感凭据

包括 Probe 注册凭据和认证密钥在内的敏感服务端凭据，会在写入数据库前使用 AES-256-GCM 加密。

iOS 凭据

iOS App 保存的认证令牌使用 Apple Keychain Services 保护。

用户仍应只授予基础设施集成所需的权限。

私有监控

Docker Probe，无需入站暴露

Probe 部署在它需要观察的网络内部。

仅出站通信

Docker Probe 在授权的私有网络内运行，并主动向 OpsHome Cloud 发起出站 HTTPS 连接。OpsHome Cloud 不会直接连接你的 LAN。

无需公开管理界面

无需开放入站防火墙端口、配置端口转发，或通过反向代理公开私有管理面板。

本地访问范围由你控制

Probe 可以访问你配置的 Proxmox、群晖、Docker、Linux、HTTP、HTTPS 或 TCP 目标。请谨慎选择目标和权限。

运行数据

Probe 上报健康状态、状态变化、事件和有限的资产元数据，帮助你了解已连接的基础设施。

查看 Docker Probe 安全模型 →查看部署说明 →

访问控制

由用户控制连接的基础设施

已认证账户上下文

请求会在已认证的账户上下文中进行校验。用户控制哪些基础设施连接到 OpsHome，以及授予哪些权限。

最小权限

在支持的场景下使用专用监控账号或受限权限，避免为监控集成使用不必要的管理员凭据。

公开状态页

可选的公开状态页只展示选定的状态信息，不应暴露私有 IP、主机名、URL、容器名称、内部路径、API 密钥或 Probe 标识符。

共同责任

用户负责本地主机、Docker 安装、凭据、权限、网络策略以及选择的监控目标。

版本完整性

固定 Docker Probe 的准确镜像版本

Docker Probe 版本会发布不可变的 OCI 镜像摘要。部署时可以固定准确版本，而不仅依赖可变标签。

docker pull opshomenoc/opshome-noc@sha256:<published-digest>
镜像摘要用于标识部署时使用的准确镜像内容。你可以在 Docker Hub 查看当前公开的版本和摘要。
